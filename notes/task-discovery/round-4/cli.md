## レンズ総評

実装は思ったより CLI が進んでいて、`--help` / `--version` の第一級化と優先順位のテストまで済んでいる
（`app/src/main.rs:5514-5557`、`app/src/main.rs:5914-5927`）。
したがって「GUI アプリゆえに CLI が無い」という単純な話ではなく、
「起動ディレクトリ 1 個だけを正式な入力として、それ以外は内部テスト用の env に逃がしている」状態である。
最初に片付けるべきは r4-cli-01 の方針決定で、これがないと
r4-cli-08 の stdin や r4-cli-12 のフック公開が「能力不足」か「非目的の逸脱」か判定できない。

確定度と費用対効果が高いのは r4-cli-02、r4-cli-05、r4-cli-06、r4-cli-07 の文書・診断・終了コード群で、
いずれも依存追加なし・小さな差分で、既存の `--version` 契約を壊さずに直せる。
次に価値が高いのは r4-cli-03 と r4-cli-04 で、`.desktop` の `%f` が既に
「ファイルを渡す」と宣言しているのにアプリが捨てているという矛盾を解消する。
単一インスタンス（r4-cli-09）と D-Bus アクティベーション（r4-cli-10）は
コードから挙動を証明できず未確認のまま残すのが正確で、
ライフサイクルレンズとの重複を避けつつ CLI 側の契約だけを先に定義するのが妥当である。
