## 兼任クラスタ総評

最も多く統合されたのは監視系で、B の `r1-qual-05` / `r1-qual-06` / `r1-qual-09` / `r3-state-10` が R6-A-04（エラー状態の保持・復旧）へ、`r3-state-05` / `r3-state-06` / `r3-state-07` / `r1-gap-10` / `r3-async-01` / `r3-input-03` が R6-A-05（世代ガード・親由来・自己操作抑制）へ集約された。次いで検索系 E が R6-A-17（由来・部分失敗・一致箇所の可視化, 6 件）と R6-A-20（一致・ソート意味論, 6 件）へ、設定系 D が R6-A-10（永続化基盤, 5 件）と R6-A-12（設定 UI と終了時保存, 5 件）へ統合された。C の進捗チャネルと E の検索キャンセル・全コピーは R6-A-08 として横断的に 1 項目へまとめている。

明示的な重複解消は、`r1-gap-01` + `r1-plat-08`（OS ファイルクリップボード）、`r1-gap-03` + `r1-code-11`（open/reveal の成功文言）、`r2-cmp-03` + `r2-scn-09`（名前付き検索と保存ビュー）、`r4-cfg-05` + `r4-cfg-06`（検索上限）の 4 組。`r3-osint-01` は親が「`r1-code-11` / `r1-gap-03` と関連するが解決策が異なるため別項目として残すかを第 6 パスで判断」と委ねていたが、根本因を「OS 連携 API が単発呼び出しで結果も fallback も持たないこと」と捉え、R6-A-02 へ併合した。

事実誤認による却下は A〜E の範囲では 0 件。親が既に却下した `r2-a11y-09`（O クラスタ）と数値訂正済みの `r1-code-10`（M クラスタ）は本範囲外のため再掲しない。`r4-cfg-02` は親判定どおり「既知(低優先)」として残し、silent drop はしていない。未確認 4 件（R6-A-03 / 06 / 07 / 09）はいずれも外部仕様または未計測値に依存するため「確定」を避けた。`r4-cfg-08` / `r4-cfg-10` / `r3-input-01` は F / H / L クラスタからも言及されるが、本ファイルでは D / E 側の主担当として 1 回だけ計上している（他クラスタ側での重複計上は親が統合時に解消すること）。
